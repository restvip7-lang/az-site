Главные причины для нового сайта:

1. **Critical. Фотографии объектов не загружаются.** Оптимизация изображений Vercel отвечает `402 OPTIMIZED_IMAGE_REQUEST_PAYMENT_REQUIRED`: исчерпан лимит тарифа. На странице Махмутлара 6 из 8 фото не загрузились, вместо них виден alt-текст.
2. **Critical. Заявки никуда не сохраняются.** Форма только открывает WhatsApp с текстом. Если у посетителя нет WhatsApp на этом устройстве или он закрыл вкладку, лида нет. Нет ни CRM, ни письма, ни цели в аналитике.
3. **Critical. Нет политики конфиденциальности и согласия на cookies.** Форма пишет «соглашаетесь на обработку персональных данных», но ссылки на политику нет нигде на сайте. Для русскоязычного сайта с аудиторией из РФ (152-ФЗ) и компании в Турции (KVKK) это юридический риск.
4. **High. База данных отвечает нестабильно.** За 7 дней в логах Vercel 94 случая «admin objects: no answer in 8000 ms» (27 посетителей), один эпизод `EMAXCONN max client connections reached, limit: 200`. Функции работают в регионе `iad1` (США), база Supabase во Франкфурте: каждый запрос пересекает океан.
5. **High. Нет английской версии.** На azpo.ru и azpo.com есть /en/. Новый сайт перенаправляет /en/ на русскую главную: после переезда англоязычный трафик и позиции будут потеряны.

Сильные стороны нового сайта (проверено): Lighthouse мобильный 97/97/96 на главной, CLS 0, 0 битых внутренних ссылок из 268 проверенных, корректные canonical, sitemap на 1 978 URL, schema `RealEstateListing`/`BreadcrumbList`/`FAQPage`, llms.txt, нормальная авторизация админки (scrypt, хеш токенов, лимит попыток), заголовки безопасности, сборка, `tsc` и `eslint` без ошибок.

## Детали по проблемам

### C1. Фото объектов отдают 402 — Critical
- **Где:** `next.config.ts:28-43` (`images.remotePatterns` для api.azpo.ru, `deviceSizes` 5 размеров × `formats` AVIF/WebP); компоненты `PropertyCard.tsx`, `Gallery.tsx`, `ObjectPage.tsx` используют `next/image`.
- **Доказательство:** запрос `GET /_next/image/?url=https://api.azpo.ru/api/files/property-images/…&w=640` → `402`, заголовок `x-vercel-error: OPTIMIZED_IMAGE_REQUEST_PAYMENT_REQUIRED`. Из 25 URL изображений на `/ru/turkey/alanya/mahmutlar/` 23 фото объектов вернули 402 (2 логотипа из кеша — 200). В браузере на мобильном: 6 из 8 фото карточек не загрузились, вместо фото виден alt-текст. В консоли 73 ошибки `status of 402`.
- **Влияние:** каталог без фото — главный продающий элемент не работает. Каждый новый размер или фото ухудшает ситуацию. Lighthouse этого не замечает, потому что его прогоны попали в кеш.
- **Исправление:** (а) перейти на платный тариф Vercel с лимитом оптимизаций, или (б) отдавать фото без оптимизации Vercel: `unoptimized` для внешних фото и заранее сжатые WebP-превью (при переносе фото в админку — генерировать 2–3 размера при загрузке, как уже делает `admin/api/upload`), или (в) свой loader через CDN/imgproxy на VPS. Сократить `deviceSizes`.
- **Критерий:** 0 ответов 402 на 100 случайных фото из sitemap; 0 ошибок в консоли на каталоге и карточке; повторная проверка через 30 дней трафика.

### C2. Заявки не сохраняются — Critical
- **Где:** `src/components/LeadForm.tsx:13-17` — `window.open(wa.me…)`, `<form>` без `action`.
- **Доказательство:** код; на `/ru/contacts/` форма `action=null`, поля name/phone. Комментарий в коде: «After launch it will also save the lead» — не сделано.
- **Влияние:** потеря лидов (десктоп без WhatsApp, блокировщики всплывающих окон, передумал в WhatsApp). Невозможно посчитать конверсию.
- **Исправление:** серверный обработчик (route handler) с сохранением в таблицу `leads`, уведомление менеджеру (e-mail/Telegram), защита от спама (honeypot + лимит по IP), затем уже WhatsApp как опция. Отправка — только после согласования, куда идут лиды (на azpo.ru есть `/api/form/create` — не трогать без разрешения).
- **Критерий:** тестовая заявка появляется в админке и приходит уведомление за < 1 мин; работает без WhatsApp; цель в аналитике срабатывает.

### C3. Нет политики конфиденциальности и cookies — Critical
- **Где:** нет страницы; `LeadForm.tsx:29` (текст согласия без ссылки); `src/app/[lang]/layout.tsx:87-93` (Vercel Analytics, Speed Insights, Яндекс Метрика с `webvisor:true` при заданном `NEXT_PUBLIC_YM_ID`).
- **Доказательство:** поиск по коду `privacy|политик|cookie` вне админки — 0 файлов; на `/ru/contacts/` ссылок на политику 0.
- **Влияние:** 152-ФЗ (сбор ПДн граждан РФ, Вебвизор), KVKK (Турция), GDPR для посетителей из ЕС. Штрафы, блокировки рекламы, недоверие.
- **Исправление:** страница политики (юрист компании), ссылка в футере и у каждой формы, чекбокс или явный текст согласия со ссылкой, баннер cookies до включения Метрики/Вебвизора.
- **Критерий:** ссылка на политику на всех страницах и у всех форм; Метрика не грузится до согласия (проверка во вкладке Network).

### H1. Нестабильная БД — High
- **Где:** `src/lib/db/index.ts:43` (`max: 3`), `src/lib/api.ts` / `src/lib/admin/catalogue.ts` (таймауты 8 с / 5 с / 20 с), регион функций по умолчанию `iad1`.
- **Доказательство:** Vercel runtime errors за 7 дней: «Admin objects are not available Error: admin objects: no answer in 8000 ms» — 94 раза, 27 пользователей, последний 27.11 21:53 UTC; «EMAXCONN max client connections reached, limit: 200» — 18 раз 26.11; «Task timed out after 300 seconds» — 42 раза 25.11. Ответы содержат `x-vercel-id: fra1::iad1::…`; `/admin/api/diag/` показывает `db.ms: 1132`.
- **Влияние:** при таймауте каталог строится без объектов из админки или из устаревшего кеша; новые/изменённые объекты могут не появляться; медленные страницы при промахе кеша (карточка — 4 080 мс при первом запросе).
- **Исправление:** задать регион функций `fra1` (Vercel → Settings → Functions или `vercel.json` `regions`), пул через Supavisor transaction mode с ограничением соединений, кеш каталога в одном месте (Data Cache/KV), мониторинг количества соединений.
- **Критерий:** 0 ошибок «no answer» и EMAXCONN за 7 дней; `db.ms` < 150 мс; холодная карточка < 1,5 с.

### H2. Нет английской версии — High
- **Где:** `src/lib/i18n.ts:4` (`LANGS = ["ru"]`), `src/middleware.ts:43` (`/en/` → `/ru/`).
- **Доказательство:** `/en/` → `/ru/`; `/en/property-turkey/1046` → русская карточка. На azpo.ru `/en` отдаёт 200 с английским контентом; на azpo.com — тоже.
- **Влияние:** после переключения домена англоязычные страницы исчезнут из поиска, редирект на русский язык — плохой UX и сигнал для Google.
- **Исправление:** добавить `en` в LANGS с переводами, hreflang ru/en/x-default; до готовности переводов — не переключать домен или оставить EN на старом сайте.
- **Критерий:** все шаблоны доступны на /en/ с 200, hreflang взаимный, проверка в Search Console без ошибок.

### H3. Публичный тяжёлый diag — High
- **Где:** `src/app/admin/api/diag/route.ts:101-103` — ветка `?dates` выполняется до проверки `currentStaff()`.
- **Доказательство:** код; `/admin/api/diag/` анонимно отдаёт 200 с состоянием БД, хранилища, блога, фида (проверено). `?dates` анонимно не вызывался, чтобы не нагружать сервер.
- **Влияние:** любой может многократно дёрнуть endpoint с `maxDuration 300` и десятком внешних запросов — расход лимитов Vercel, нагрузка на azpo.ru/azpo.com, раскрытие инфраструктуры.
- **Исправление:** требовать вход сотрудника для всего diag (или секретный токен), убрать `?dates` в production.
- **Критерий:** анонимный запрос к `/admin/api/diag/` и `?dates` → 401/404.

### Боевые azpo.ru и azpo.com (P1–P8)
Проверено из браузера на компьютере пользователя (из облака эти домены недоступны). Оба домена отдают одинаковое Next.js-приложение (nginx/1.29.4, `x-powered-by: Next.js`).
- **P1:** `<meta name="robots" content="noindex, nofollow">` на карточках объектов 44, 100, 300, 500, 700, 900, 1000, 1040, 1046 в RU и EN (18/18). Каталог объектов практически не индексируется. Плюс в `robots.txt` строка `Disallow: /property-turkey/[0-9]+` — регулярные выражения robots.txt не поддерживает.
- **P2:** `<link rel="canonical" href="//">`, hreflang `x-default=// | en=// | ru=//`; у `/ru/citizenship` canonical `//about`. Lighthouse: «Недопустимый URL (//)».
- **P3:** `/sitemap.xml` → 200 HTML (`/en/sitemap.xml`), несуществующие страницы → 200 с `noindex` (soft 404). Сайтмап есть только у блога WordPress (`/ru/blog/sitemap_index.xml`, lastmod 02.04.2025).
- **P4:** `og:image` = `http://localhost:3000/og-image.jpg` / `azpo.png` — превью в мессенджерах сломано.
- **P5:** в ответах нет `strict-transport-security`, `content-security-policy`, `x-frame-options` (Lighthouse подтверждает отсутствие HSTS и защиты от кликджекинга).
- **P6–P8:** см. таблицу.

Новый сайт исправляет P1–P5 и P8 by design — это главный аргумент в пользу переезда после закрытия C1–C3.
